# 遗留问题（Known Issues / External Blockers）

> 校准日期：2026-09-15（main，含 PR #1–#14）  
> 对照：`docs/DOD_STATUS.md`、`docs/DESIGN_COMPLETION.md`、`docs/DESIGN.md`

本文列出 **当前实现之后仍然遗留** 的问题。仓库内 DESIGN §26 验收条目已无 **PARTIAL**；下列问题按性质分类，便于排期与对接外部工具。

---

## A. 外部依赖（EXTERNAL）— 本仓库刻意不内置

| ID | 问题 | 影响 | 解锁方式 |
|----|------|------|----------|
| E1 | **真 Cubism 姿态渲染 / `.moc3` 预览** | Gate 7 / 姿态 QA 默认用 mock-rig 网格变形，不是 Cubism Editor 实拍 | 安装 Cubism 相关工具链；后续可接导出链路（当前未内置 SDK） |
| E2 | **psd2live 实机导出 `.cmo3` / `.moc3`** | 下游「正式 Cubism 工程」需外部程序 | 本机安装 psd2live，设置 `AI2LIVE_PSD2LIVE_CMD`（或 MCP URL）。**永不把 GPL 源码 vendor 进本仓** |
| E3 | **AutoLive2d 实机导入** | 默认写导入包 + mock runner，不启动真实 AutoLive2d | 设置 `AI2LIVE_AUTOLIVE2D_CMD` 指向可执行文件 |
| E4 | **生产级图像生成 / VLM 审核质量** | 无密钥时 dry-run mock；有密钥质量取决于供应商与提示词 | `AI2LIVE_GROK_API_KEY` / `OPENAI_API_KEY`；可选 `AI2LIVE_VLM_LIVE=1` |
| E5 | **OpenCV TELEA 默认不在 CI** | inpaint 可能走 telea-like / neighbor_blend | `pip install` worker 的 `[opencv]` extras，并启动 image worker |

相关环境变量见根目录 `.env.example` 与 [mock-rig.md](./mock-rig.md)。

## B. 能力边界（已实现，但质量 / 覆盖仍有上限）

| ID | 问题 | 说明 |
|----|------|------|
| Q1 | **单张设定图分割仍依赖启发式 + see-through** | 非端到端语义分割大模型；复杂发型 / 交叉手臂 / 侧脸会降质 |
| Q2 | **遮挡补全 / 表情差分** | 已接 min-region inpaint 与 imageEdit；dry-run 与弱密钥场景仍可能邻域混合 / ROI 变形，观感不如强模型 inpaint |
| Q3 | **Master「绑骨友好」** | `init --text` 产合成 Master；真实立绘需用户提供设定图或接生图 API，Gate 0 不能替代美术规范 |
| Q4 | **Mock Rig ≠ 商业 Live2D 工程** | 可验证管线与极值洞，不能替代 Cubism 里的变形器 / 物理 / 最终验收 |
| Q5 | **评测集为合成夹具** | `evals/*` 合计可到 100%，不代表任意商业立绘零人工 |

## D. 明确「不是 Bug」的设计选择

1. **PSD 是第一优先交付物**；Cubism 导出是可选外部步骤。  
2. **Mock 下游在无二进制时视为一等公民**，以保证 CI / dry-run 可完成 DoD「自动送入 ≥1 Rig backend」。  
3. **不复制 psd2live GPL 实现** 进入本仓库。  
4. **Doctor / 日志永不打印密钥内容**。
