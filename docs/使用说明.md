## 1. 产品能做什么（当前）

`ai2live` 是 **Live2D 资产编译管线**：从文本或一张角色设定图出发，产出：

| 优先级 | 产物 | 路径 |
|--------|------|------|
| 主产物 | 规范分层 PSD | `exports/<名称>_layers.psd`（另有工作副本 `psd/character.psd`） |
| 清单 | 导入对照 | `exports/import_manifest.json` |
| 下游包 | AutoLive2d / psd2live 导入协议 | `builds/autolive2d/`、`builds/psd2live/`（默认走 **mock 一等后端**；真二进制可选） |
| 报告 | 管线 / 质检 / 闸门 | `validation/pipeline_report.json` 等 |

**LEFT/RIGHT = 角色自身左右**（非观察者左右）。psd2live **永不 vendor GPL 源码**，仅外部协议 / mock。

## 2. 环境与安装

- Node.js **≥ 20**
- pnpm **9.x**（仓库锁定 `pnpm@9.15.0`）

```bash
git clone https://github.com/windssea/ai2live.git && cd ai2live
pnpm install
pnpm -r build
pnpm -r test
```

环境变量模板：根目录 [`.env.example`](../.env.example)。  
自检（不打印密钥）：

```bash
pnpm ai2live -- doctor
# 或：pnpm --filter @ai2live/cli exec node dist/cli.js doctor
```

下文用 `ai2live` 表示：`pnpm ai2live -- <子命令…>` 或 `pnpm --filter @ai2live/cli exec node dist/cli.js <子命令…>`。

## 3. 推荐主路径：一张设定图 → PSD（+ Live2D 包）

### 3.1 统一控制台（推荐）

```bash
pnpm --filter @ai2live/studio dev
# http://127.0.0.1:5173
```

1. **导入设定图**（上传或本地路径）
2. 选择 provider（默认 `grok`）；无密钥请勾选 **dry-run**
3. 点击 **一键完成全部 / Run All**
4. 右侧下载 **PSD**，查看状态机、产物路径、`pipeline_report`

控制台还支持：状态 / 人工接管（NEEDS_REVIEW）、图层替换上传。

### 3.2 CLI 一键

```bash
export AI2LIVE_MODEL_DRY_RUN=1
ai2live run ./my-character --from-image ./设定图.png --dry-run --provider grok
```

有密钥时可去掉 `DRY_RUN`，设置 `AI2LIVE_GROK_API_KEY`（或 OpenAI），图层规划与补全质量会更好。

**默认行为要点（batch8+）：**

- 开启 vision-review 双裁决（dry-run 下 VLM 为 mock）
- `AI2LIVE_USE_MOCK_RIG=1`：姿态极值与下游默认走 mock-rig（无需本机 Cubism）

## 4. 文本建项

```bash
export AI2LIVE_MODEL_DRY_RUN=1
ai2live init ./my-character --text "黑发少女，正面半身，清晰五官，便于绑骨"
ai2live run ./my-character --dry-run
```

会生成可过 Gate 0 的合成 Master + 图层模板，再进入全流程。

## 5. 已有图层项目：编译 / 校验

```bash
node examples/simple-character/generate-assets.mjs   # 如缺 PNG
ai2live compile ./examples/simple-character
ai2live validate ./examples/simple-character
# 或
pnpm compile:example && pnpm validate:example
```

## 6. CLI 命令一览（与当前实现对齐）

```text
ai2live init <dir> --text "..."
ai2live run|pipeline <dir> [--from-image] [--provider] [--dry-run] [--json-events] [--apply-repair] ...
ai2live unattended <dir>          # 已弃用别名，等同 run
ai2live compile|validate <dir>
ai2live segment <dir> [--feather] [--split-bilateral] [--debug]
ai2live occlusion|expressions|repair|downstream <dir>
ai2live doctor [--json]
ai2live providers
ai2live status <dir>              # 状态机 .ai2live/state.json
ai2live agent plan|diagnose|repair <dir> [--provider] [--apply|--apply-stub]
ai2live image edit --prompt ... --input ... [--provider] [--project]
ai2live revision list|checkout|resume ...
ai2live layer replace <dir> <layerId> --png <path>
ai2live eval                      # → evals/last-report.json
```

分步排障可单独跑 `segment` / `occlusion` / `expressions` / `repair` / `downstream`。

## 7. 模型提供方

| Provider | 环境变量 | 用途 |
|----------|----------|------|
| **grok**（默认） | `AI2LIVE_GROK_API_KEY` / `XAI_API_KEY` | 规划、诊断、imageEdit、可选 VLM |
| **openai** | `OPENAI_API_KEY` / `AI2LIVE_OPENAI_API_KEY` | 同上（ChatGPT / Images） |
| **codex** | `AI2LIVE_CODEX_BIN` 等 | 本地 Codex CLI |

无密钥：`AI2LIVE_MODEL_DRY_RUN=1`。详见 [providers.md](./providers.md)。

---

## 8. 评测

```bash
ai2live eval
# 或：node evals/run-all.mjs
```

套件：`hair-stress` / `occlusion-stress` / `flat-image` → `evals/last-report.json`。  
当前仓库基线目标：**合计通过率 100%**（以你本地最近一次 `last-report.json` 为准）。

## 9. MCP / 图像 Worker / Mock Rig

- MCP：`pnpm --filter @ai2live/mcp-server exec node dist/index.js`（tools：compile/validate/providers/agent_plan + design/view/asset/layer/task/inspect/…）
- Python worker：`PYTHONPATH=services/image-worker-python/src python -m ai2live_worker.main --port 8090`；可选 `pip install '.[opencv]'`
- Mock rig：见 [mock-rig.md](./mock-rig.md)

## 11. 遗留问题（摘要）

**仓库内 DESIGN 验收已无 PARTIAL**；未闭合项均为 **EXTERNAL** 或质量上限类问题。完整列表见 **[遗留问题.md](./遗留问题.md)**。

要点：

1. 真 Cubism / `.cmo3` `.moc3` 需本机 `AI2LIVE_PSD2LIVE_CMD`（GPL 二进制不进仓）
2. 真 AutoLive2d 需 `AI2LIVE_AUTOLIVE2D_CMD`
3. 生产级生图 / VLM 需 API Key 与费用（否则 dry-run mock）
4. CI 默认未必有 OpenCV TELEA（有纯 Python / 邻域回退）
